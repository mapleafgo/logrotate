# 以 Logback 为对标的 Go 文件轮转设计

状态：早期提案，仅供追溯。最终采用 `/v2` 下的 `Open(Config)`、MiB 配置和后台归档维护，未采用下文的双入口方案。当前规则见 [README](../../../README.md)。范围是单进程独占活动文件及归档目录，不是通用日志框架。依据：[Logback 滚动策略](https://logback.qos.ch/manual/appenders-rolling.html#SizeAndTimeBasedRollingPolicy)。

## 对外接口

保留 Open(Config) 和 OpenAsync(FileSink, AsyncConfig)。新增 OpenRolling(RollingConfig) (*Writer, error)，明确选择新磁盘格式，不让同一字段在补丁升级时改变含义。两个同步入口共享内部写入、同步和关闭逻辑；不导出策略接口、时钟接口或文件系统接口。Writer 实现 io.WriteCloser，并提供 Sync；标准 log 或 slog handler 直接接收它。并发调用方使用 AsyncWriter，包装成功后由它独占并关闭 sink。

目标配置示例（不是当前版本 API）：

~~~go
cfg := logrotate.RollingConfig{
    Filename: "logs/app.log",
    Daily: true, Location: time.UTC,
    MaxFileBytes: 128 << 20,
    HistoryDays: 7, TotalArchiveBytes: 2 << 30,
    Compress: true,
}
~~~

Filename 必填；Daily、Compress 为 bool；Location 为 *time.Location，nil 取本地时区；两个字节字段为 int64，HistoryDays 为 int。负数拒绝；零值关闭相应条件，不表示清空历史。只有 Filename 时只追加，不启动维护。TotalArchiveBytes 可单独启用，不照搬 Logback 要求同时配置 maxHistory 的限制。

## 切分、命名与保留

- 非空 Write 前先判断是否跨自然日，再判断非空活动文件加本条是否超过字节阈值；两个条件命中只切一次。等于阈值不切；单条超限整条写，不造空卷。无写入不定时切。启动时非空活动文件按 mtime 在配置时区归日。时间回拨不倒退已打开卷的周期。
- 活动路径固定。新卷位于同文件系统的专属目录（示例 logs/app.log.archives/），格式 YYYY-MM-DD.N，从 0 开始，gzip 仅加 .gz。纯大小模式用封存日期标记，不因跨日切分。重启按同日所有正式卷和待处理卷的最大编号续号；碰撞不覆盖，权限等非不存在错误立即返回。目录专用且不得由外部轮转工具同时管理。
- 在 OpenRolling 和每次封存后执行维护。HistoryDays=N 保留今天及前 N−1 个自然日（不是 N 个有日志的日子），按日历计算，不以 24h 作一天。先删过期卷，再按日期、数字卷号从旧到新删到总量达标。因此总量可能缩短实际历史。按正式归档实际字节计；不计活动文件、临时产物或未完成归档。只处理规范名称的普通文件，不跟随符号链接；删除失败不扣账，保留错误以供查询。两个条件都未启用时不做清理扫描。

## 封存与恢复

先同步、关闭活动文件，移入专属目录的唯一原始卷；再以追加方式恢复活动路径，不用截断作兜底。若封存失败，重开原路径并返回本次写入错误；若新活动文件创建失败，保留已封存卷，允许下次重试打开。第一版串行维护以减少故障状态，不承诺轮转低延迟。

启用压缩时以专属待处理后缀保存原始卷，流式写同目录临时 gzip，完成 gzip.Close、文件 Sync 和 Close 后再发布正式名；最后才删原始卷。支持目录同步的平台，在跨目录改名和发布后同步相应目录；不对所有文件系统承诺断电原子性。重启遇到仅原件或临时文件加原件则从原件重做；正式卷和原件并存时验证解压内容与原件一致后才移除原件，否则两者保留并报告冲突。恢复先于保留清理。维护失败但当前记录写成功时不得返回虚假写失败诱发上层重发；Writer 提供 MaintenanceError() error 查询最近维护结果，异步使用时该查询须可并发读取。未恢复维护错误由 Close 一并返回。

## 异步交付

沿用有界 channel、单消费者、默认阻塞和显式 FullDropNewest；拒绝未知策略。短锁只保护关闭标记和在途登记，不包围阻塞发送。Close 先关准入、唤醒等待者，再等在途退出、关队列并排空，最后同步、关闭 sink；重复 Close 返回同一结果。关闭后的 Write/Sync 返回可由 errors.Is 判别的关闭错误。已入队内容必须拥有独立副本。容量不足丢弃时返回原有 ErrDropped，不按日志级别猜测可丢性。

Write 成功只表示入队。Sync 是 FIFO 屏障：处理之前已入队的写入并调用 sink.Sync，不等待尚未入队的生产者。一次后台写失败或短写（io.ErrShortWrite）不能被后续成功洗掉：保留首个交付错误直至 Close，Sync 与 Close 均报告；LastError 仍表示当前健康状态。Sync 不会重写已经部分成功的记录。

## 分批合并及发布门槛

1. **兼容修复**：先测试后修复并发关闭、短写、错误留存、日期选名的权限错误和编号移位失败后继续覆盖。旧日期合并 gzip 在同目录临时副本中完成后替换，旧编号链同时处理压缩失败留下的原件。纠正旧 MaxBackups=0 的文档：纯大小模式不留备份。保持旧命名和零值行为。门槛：阻塞 sink 下交错 Write/Sync/Close，无 panic 或挂起；失败→成功→关闭仍报告失败；改名前后比较保留记录内容。
2. **新入口和磁盘协议**：内部用纯函数做触发判断和保留计划；真实文件操作集中在封存、压缩与恢复函数，只对注入失败所需的操作设私有测试接点。用临时目录覆盖阈值±1、超大记录、跨午夜、DST、重启续号、同日多卷和磁盘不足。在封存、重开、压缩、发布、删原件各步中断后重启，按记录 ID 验证恢复结果；正式 gzip 均可完整解压，相似文件未动。运行 go vet ./...、go test -race ./...。
3. **灰度迁移**：先停止旧 writer 并成功 Close，再以同一活动路径启用新入口。新目录只管新卷；旧归档不计入新预算，不自动迁移或删除。先给两处预留空间、配置旧卷到期清理，并更新采集器匹配规则；回滚时也先关闭新 writer，旧入口继续追加活动文件，新归档保持原状。
4. **性能门槛**：相同文件系统、同步策略、记录大小和并发度下采集普通写与切卷写的 P99、吞吐、分配及队列峰值；不以入队耗时代替落盘耗时。仅在轮转延迟超出业务预算时引入单个有界维护 worker，以磁盘待处理卷为事实源，不按卷无限启动 goroutine；只有满队列内存基准显示需要时再加字节预算。
