# Logback 滚动与归档保留：研究备注

依据[官方滚动手册](https://logback.qos.ch/manual/appenders-rolling.html#TimeBasedRollingPolicy)和 Logback **1.5.18**（标签 `v_1.5.18`、提交 `b2a02f065379a9b1ba5ff837fc08913b744774bc`）。下述失败路径是该版本源码的行为，不是跨版本承诺。

- **活动文件重开失败。** 先关闭旧输出流，再调用滚动策略，最后尝试打开活动文件。策略抛出 `RolloverFailure` 时设置追加模式以避免截断，仍尝试重开；但重开本身抛出 `IOException` 时只记录错误，不回滚归档，也不立即重试或恢复旧流。正常关闭后输出流已置空，本次事件仍进入写入路径，可能因空流而丢失。[滚动与追加](https://github.com/qos-ch/logback/blob/b2a02f065379a9b1ba5ff837fc08913b744774bc/logback-core/src/main/java/ch/qos/logback/core/rolling/RollingFileAppender.java#L179-L236) · [关闭与写入](https://github.com/qos-ch/logback/blob/b2a02f065379a9b1ba5ff837fc08913b744774bc/logback-core/src/main/java/ch/qos/logback/core/OutputStreamAppender.java#L126-L136) · [写入调用](https://github.com/qos-ch/logback/blob/b2a02f065379a9b1ba5ff837fc08913b744774bc/logback-core/src/main/java/ch/qos/logback/core/OutputStreamAppender.java#L215-L245)
- **压缩。** 手册按归档文件名后缀选择压缩。时间策略在设置固定活动文件名时先将旧文件改名为 `.tmp` 再异步压缩；未设置时直接异步压缩旧周期文件。归档清理单独提交，不等待压缩完成。以该版 gzip 为例：直接写最终 `.gz` 路径，捕获压缩异常并记录后仍尝试删除源文件，不能假定压缩失败一定保留原件。[滚动策略](https://github.com/qos-ch/logback/blob/b2a02f065379a9b1ba5ff837fc08913b744774bc/logback-core/src/main/java/ch/qos/logback/core/rolling/TimeBasedRollingPolicy.java#L148-L177) · [gzip 实现](https://github.com/qos-ch/logback/blob/b2a02f065379a9b1ba5ff837fc08913b744774bc/logback-core/src/main/java/ch/qos/logback/core/rolling/helper/GZCompressionStrategy.java#L29-L66)
- **配额删除失败。** 手册规定 `totalSizeCap` 依赖 `maxHistory`，异步先按历史周期清理，再按容量清理；`cleanHistoryOnStart` 默认关闭。容量清理从新到旧累加匹配归档的磁盘文件长度（同周期按索引倒序），累计超过上限就尝试删除当前候选。`File.delete()` 返回 `false` 时告警并继续，只把成功项计入已删除字节数；累计扫描量不会回减，也没有当轮重试，因此实际占用仍可能超配额。[删除与计数](https://github.com/qos-ch/logback/blob/b2a02f065379a9b1ba5ff837fc08913b744774bc/logback-core/src/main/java/ch/qos/logback/core/rolling/helper/TimeBasedArchiveRemover.java#L99-L146) · [异步清理顺序](https://github.com/qos-ch/logback/blob/b2a02f065379a9b1ba5ff837fc08913b744774bc/logback-core/src/main/java/ch/qos/logback/core/rolling/helper/TimeBasedArchiveRemover.java#L238-L257) · [卷排序](https://github.com/qos-ch/logback/blob/b2a02f065379a9b1ba5ff837fc08913b744774bc/logback-core/src/main/java/ch/qos/logback/core/rolling/helper/SizeAndTimeBasedArchiveRemover.java#L30-L57)
- **超大卷。** [手册的大小与时间策略](https://logback.qos.ch/manual/appenders-rolling.html#SizeAndTimeBasedRollingPolicy)用 `maxFileSize` 触发分卷。该版在写入事件前比较已有字节数，不按剩余空间拆分单条事件，因此活动卷仍可能超出阈值。该策略拒绝非无限且小于 `maxFileSize` 的总配额；但若匹配到的最新归档单卷实际大于总配额，清理仍会尝试删除它（没有“至少保留最新卷”的规则），且之后扫描到的更旧归档也会进入删除分支。[大小触发](https://github.com/qos-ch/logback/blob/b2a02f065379a9b1ba5ff837fc08913b744774bc/logback-core/src/main/java/ch/qos/logback/core/rolling/SizeAndTimeBasedFileNamingAndTriggeringPolicy.java#L144-L192) · [配置校验](https://github.com/qos-ch/logback/blob/b2a02f065379a9b1ba5ff837fc08913b744774bc/logback-core/src/main/java/ch/qos/logback/core/rolling/SizeAndTimeBasedRollingPolicy.java#L18-L38) · [配额循环](https://github.com/qos-ch/logback/blob/b2a02f065379a9b1ba5ff837fc08913b744774bc/logback-core/src/main/java/ch/qos/logback/core/rolling/helper/TimeBasedArchiveRemover.java#L115-L146)
